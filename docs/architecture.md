# 系统架构与算法

## 职责边界

**FPGA**：八通道 ADC 扫描、压力调理、触发/释放、四声部分配、音高与表情、ADSR、加法分量、音效、DAC 串行输出、曲谱调度、数字观察和视频输出。

**ESP32-S3**：UART 帧解析、BLE 分片/转发、认证会话、中文 OLED。它不负责逐采样乐音合成，不把手机音频转接成 FPGA 乐音。

**小程序 / 电脑曲库**：曲谱搜索与编译、蓝牙事务、自定义音高、设备状态与交互。手机发曲谱后，练习计时与音符执行由 FPGA 完成，不依赖手机定时器精确打拍。

## 输入与四声部

`mcp3208_adc`、`mcp3208_scanner` 扫描八个模拟通道；四个 FSR 分别做压力调理与迟滞触发，两个摇杆提供四个模拟轴。`zone_note_map` 把区域事件映射为音高、音色和代际，`voice_allocator_regions` 维护声部归属，音组/八度改变通过单独的实时改调事件更新持有声部。

四声部各自保存基频、音色、ADSR、压力和 generation。释放事件仍匹配原声部；音色切换不会把已持有声部的尾音改为另一种音色。`poly_synth_regions` 负责基础合成与包络。

## 每声部加法层

`poly_additive_engine` 为每个声部保留独立上下文。谐波 k 的相位由该声部基本相位乘 k 得到，逐分量计算正弦与权重，再累加。两条运算通道各服务两个声部，时分运算在约 48 kHz 的每采样周期预算内完成；这是一种资源复用结构，不是 128 套物理乘法器。

J2 X 改变分量掩码并做平滑交叉淡入；每声部压力 × 包络的增益继续作用于该声部的分量层。高频分量受抗混叠边界限制。四声部 × 每声部最多 32 分量，是运算容量的描述，**不是 128 个可独立按键演奏、任意调谐与独立包络的振荡器**。

正弦 ROM 与相位增量常量是波形函数的系数，没有录制乐音播放路径。约 55 Hz 的测试模式便于观察 32 个低频谐波；必须结合真实运算有效信号/相位上下文与输出频谱验证，不能只凭“32”状态文字计数。

## 效果与输出

基础声部与各自加法层混合后进入合唱/延迟或 FDN 空间效果，J2 Y 决定湿度。`pcm_output_stage` 执行有界增益、对称饱和、只衰减的用户电平和启动淡入；`pt8211_tx_mono` 驱动板载 DAC。配置中的“衰减量 0”与内部“Q6 增益 64”语义不同，顶层负责换算。

音频域约 **12.288 MHz / 256 ≈ 48 kHz**。实际采样率、PLL 误差与边界时序以本次构建配置及实测为准；STA 报告的 Fmax 是能力指标，不是当前工作频率。

## 显示

`display_capture` / `display_trace_engine` 采集数字音频，显示侧按帧使用稳定快照，`display_dashboard` 生成布局，`tmds_encoder` / `dvi_tx_ddr` 在 HDMI 接口输出视频。显示档为 640×480，显示器可能按自己的策略缩放。FFT 为 1024 点，48 kHz 下频率间隔约 46.875 Hz，界面展示 0–6 kHz 区域。

波形、FFT 与 XY 使用明确的数字节点；XY 的 X 是声部基础混合，Y 是最终左右声道均值，**不是两根模拟探头，也不是两个完全独立音源**。波形的显示放大只影响观察，不增加 DAC 电平。OLED 由 S3 经 I²C 刷新，显示与设备最新有效状态绑定，失鲜不能继续当作实时值展示。

## 曲谱与事务

曲谱编译器由客户端与服务端共享。练习曲谱使用双缓冲暂存/提交，校验与缺步检查通过后才原子发布；下载失败保留旧有效曲谱。设备示范试听使用单独的符号序列器。自由、引导、挑战的推进与发声门控分离；错区事件可显示和计数，但引导模式不会因此触发错误的新音。

配置通路同样分为 SET、COMMIT、GET，带 owner/lease、epoch 与序号检查。当前支持字段以设备 capability 为准；拒绝不支持的字段比返回虚假的“成功”更重要。
